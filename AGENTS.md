# AGENTS.md — инструкция для ИИ-агентов

Этот файл описывает проект, его структуру и правила работы с репозиторием. Прочитайте его целиком перед внесением изменений.

## Что это за проект

`mihomo-runet-mrs` — автоматически обновляемый репозиторий MRS-наборов правил для [Mihomo](https://github.com/MetaCubeX/mihomo) (Clash Meta). Дважды в сутки GitHub Actions скачивает `geoip.dat` и `geosite.dat` из ветки `release` проекта [RunetFreedom / russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat), конвертирует каждую категорию в отдельный `.mrs`-файл инструментом [MetaCubeX / meta-rules-converter](https://github.com/MetaCubeX/meta-rules-converter) и публикует результат в `main`.

**Ключевой принцип архитектуры:** собирать всегда, коммитить только при реальных изменениях. Никакой skip-логики на хэшах или state-файлах — конверсия полностью детерминирована, и идентичный upstream не должен менять содержимое репозитория.

## Структура репозитория

### Рукописные файлы (можно редактировать)

- `README.md` — документация для пользователей. Русский — основной язык, английская версия ниже. Ссылки на файлы и URL провайдеров должны оставаться рабочими: их используют конфиги реальных пользователей.
- `LICENSE` — GPL-3.0. Не трогать.
- `AGENTS.md` — этот файл.
- `.github/workflows/build.yml` — вся автоматизация (см. ниже).

### Сгенерированные файлы (НЕ редактировать руками)

Всё это перезаписывается workflow при каждом прогоне:

- `geosite/*.mrs`, `geoip/*.mrs` — сконвертированные наборы правил (~2100 файлов).
- `geosite-categories.txt`, `geoip-categories.txt`, `categories.md` — индексы доступных наборов.
- `mrs-manifest.sha256` — SHA-256 всех опубликованных `.mrs`-файлов; пересоздаётся и самопроверяется (`sha256sum -c`) при каждой сборке.
- `geoip.dat.sha256`, `geosite.dat.sha256` — хэши использованных исходных dat-файлов (информация о происхождении, не условие сборки).
- `source.commit`, `converter.commit` — коммиты upstream-снимков.
- `build-info.txt` — метаданные сборки. **Важно: не содержит метки времени** — волатильная метка создавала бы пустой коммит при каждом прогоне. Не добавляйте её обратно.
- `skipped-empty-rules.txt` — категории без правил (0-байтовые `.mrs` отбрасываются как невалидные).

## Workflow: `.github/workflows/build.yml`

- **Расписание:** `cron "37 1,13 * * *"` — 01:37 и 13:37 UTC, дважды в сутки. Вся логика в UTC, без `env: TZ`. Минута 37, а не 0 — обход пиковых задержек очереди GitHub Actions в начале часа.
- **Триггеры:** `schedule` + `workflow_dispatch` (ручной запуск для тестов).
- **Права:** `contents: write`; `concurrency` без отмены (`cancel-in-progress: false`).
- **Шаги:** checkout → setup-go → сборка конвертера (clone depth 1) → скачивание dat-баз с ветки `release` (curl с retry) → конвертация → валидация (удаление 0-байтовых `.mrs`) → замена `geosite/`/`geoip/` и регенерация индексов/манифеста → коммит и push только при изменениях.
- **Push-дисциплина:** автоматика никогда не делает force-push. После коммита — `git pull --rebase`, при реальном конфликте job падает.
- **Identity автоматики:** `github-actions[bot]` (коммит от имени бота, не пользователя).
- Автоматика коммитит только сгенерированные пути — `README.md`, `LICENSE`, workflow в коммиты бота не попадают.

## Правила для агентов

1. **Не редактируйте сгенерированные файлы** — следующий прогон всё равно перезапишет их. Правки возможны только в workflow (чтобы изменить сам процесс генерации).
2. **Сохраняйте детерминированность**: вывод конверсии при одном upstream-коммите должен быть побайтово воспроизводим. Не добавляйте в генерируемые файлы метки времени, случайные значения или пути раннера.
3. **Сохраняйте структуру путей `geosite/` и `geoip/`** — на `raw.githubusercontent.com`/main ссылаются конфиги реальных пользователей. Перемещение файлов ломает их setup.
4. **YAML workflow проверяйте перед пушем** (например, `npx js-yaml .github/workflows/build.yml`). Сломанный workflow остановит обновления на сутки до вмешательства.
5. **Пуш в main** требует у локального `gh` scope `workflow` (`gh auth status`); при его отсутствии GitHub отклоняет пуш с изменениями workflow-файлов.
6. **Тестируйте вручную** через `gh workflow run build.yml --repo nofantasysorry/mihomo-runet-mrs --ref main` и следите за прогоном (`gh run watch`). Критерий успеха после правок: прогон зелёный, и повторный запуск без изменений upstream не создаёт коммит.
7. **Ручные коммиты** делайте от имени владельца (`nofantasysorry`), не от `github-actions[bot]`.
8. Внешний интерфейс пользователя — README: любое поведенческое изменение workflow (расписание, имена файлов, форматы) требует синхронного обновления README.

## Полезные команды

```bash
# Ручной запуск и наблюдение
gh workflow run build.yml --repo nofantasysorry/mihomo-runet-mrs --ref main
gh run list  --repo nofantasysorry/mihomo-runet-mrs --workflow build.yml --limit 3
gh run watch <run-id> --repo nofantasysorry/mihomo-runet-mrs --exit-status

# Проверка манифеста локально
sha256sum --check mrs-manifest.sha256

# Проверка YAML
npx js-yaml .github/workflows/build.yml
```
